# Цели в Яндекс.Метрике — полный порядок настройки

Счётчик **108311751**, четыре цели. Код на сайте уже стоит и события шлёт —
осталось объяснить Метрике, какие из них считать целями.

## Что вообще происходит

Метрика сама по себе считает визиты и просмотры. «Цель» — это событие, которое ты
объявляешь важным, и после этого Метрика показывает по нему отдельную статистику:
сколько раз сработало, с каких источников приходили люди, которые его сделали,
и какая доля визитов до него доходит.

Тип цели, который нам нужен, — **JavaScript-событие**. Работает так: в коде вызывается

```js
ym(108311751, 'reachGoal', 'timer_start');
```

а в интерфейсе Метрики заводится цель с идентификатором `timer_start`. Метрика
связывает одно с другим по строке идентификатора. Если строки не совпадут хоть
одним символом — цель просто никогда не сработает, и никакой ошибки не будет.
Это самая частая причина «цель настроил, а она пустая».

Вызовы уже расставлены в [`static/app.js`](../../static/app.js), функция `track()` —
она же дублирует событие в GA4. Ничего в коде трогать не нужно.

## Четыре цели

| Идентификатор | Название (можно любое) | Когда срабатывает |
|---|---|---|
| `timer_start` | Запуск таймера | нажата кнопка старта тренировки |
| `workout_complete` | Тренировка завершена | тренировка доведена до конца, показан экран результатов |
| `workout_create` | Своя тренировка создана | сохранена новая тренировка (при редактировании существующей — не срабатывает) |
| `pwa_install` | Установка приложения | приложение установлено на устройство |

Идентификаторы вписывать **ровно так**, как в первой колонке: строчными, латиницей,
с нижним подчёркиванием, без пробелов по краям. Название во второй колонке — только
для твоих глаз в отчётах, его можно писать как угодно.

## Порядок действий

1. Открыть <https://metrika.yandex.ru> под аккаунтом, где заведён счётчик.
2. Выбрать счётчик **108311751** (odin-dva.ru).
3. Слева — **Настройка**, вверху вкладка **Цели**.
4. Кнопка **Добавить цель**.
5. В открывшейся форме:
   - **Название** — из таблицы выше, например «Запуск таймера»
   - **Тип условия** — выбрать **JavaScript-событие**
   - **Идентификатор цели** — вписать `timer_start`
   - «Ретаргетинг» — не включать, он нужен для рекламы
6. **Добавить цель**.
7. Повторить пункты 4–6 ещё три раза для `workout_complete`, `workout_create`
   и `pwa_install`.
8. Внизу страницы нажать **Сохранить**. Без этого цели не применятся — форма
   добавления их только складывает в список.

## Как проверить, что заработало

Первое срабатывание видно **не сразу**: Метрика обрабатывает данные с задержкой,
обычно несколько минут, иногда до получаса. Порядок проверки:

1. Открыть <https://odin-dva.ru/> в обычном окне браузера (не в режиме инкогнито —
   и лучше с выключенным блокировщиком, иначе счётчик не загрузится).
2. Запустить любую тренировку — это `timer_start`. Довести до конца — `workout_complete`.
3. Через 10–30 минут в Метрике: **Отчёты** → **Конверсии**. Там будут все четыре цели
   и число достижений по каждой.

Быстрее и надёжнее — через **Вебвизор**: он показывает запись визита с отметками
достигнутых целей на таймлайне, и там же видно, что именно человек делал.

Если цель осталась на нуле, проверять в таком порядке:

| Что проверить | Как |
|---|---|
| Идентификатор совпадает с кодом | сверить строку в Метрике с таблицей выше, посимвольно |
| Счётчик вообще загрузился | в консоли браузера на сайте ввести `typeof ym` — должно ответить `"function"` |
| Событие уходит | там же ввести `ym(108311751,'reachGoal','timer_start')` и посмотреть в Метрике через 20 минут |
| Не режет блокировщик | открыть сайт в браузере без расширений |
| Цель сохранена | вернуться в **Настройка** → **Цели**: она должна быть в списке, а не пропасть после перезагрузки страницы |

## После настройки

Скрипт выгрузки подхватит цели сам — список он берёт из API счётчика, перечислять
руками не надо:

```bash
python3 scripts/seo/fetch_metrika.py --days 28
```

Достижения лягут в `docs/analytics/data/metrika/108311751/<дата>/goals.csv`, а
`analyze.py` добавит в отчёт раздел «Цели».

## Сторона GA4

В GA4 те же четыре события приходят автоматически, заводить их не нужно — `track()`
шлёт `gtag('event', ...)` параллельно с Метрикой. Появятся в отчёте **Отчёты** →
**Взаимодействия** → **События** в течение суток.

Если захочется считать их конверсиями (это влияет на отчёты по каналам):
**Администратор** → **События** → у нужного события переключатель
**Отметить как ключевое событие**.

Отдельно заводить цели в GA4 не обязательно — для наших выводов хватает просто
количества событий, оно уже выгружается в `data/ga4/*/events.csv`.

## Зачем это всё

Сейчас в GA4 из событий только автоматические: `page_view`, `session_start`, `scroll`,
`user_engagement`, `first_visit`. По ним видно, что человек открыл страницу и
проскроллил её — и всё. Отличить «зашёл, потыкал и ушёл» от «провёл полноценную
тренировку» невозможно.

При нынешних 9 визитах в месяц цели ничего не покажут — их и не должно хватать на
выводы. Смысл в другом: когда трафик появится, история достижений уже будет
накапливаться. Заводить цели задним числом нельзя — Метрика считает их только с
момента создания.
