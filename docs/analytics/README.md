# Аналитика трафика: GSC, GA4, Яндекс.Метрика, Bing

Четыре скрипта в [`scripts/seo/`](../../scripts/seo/) тянут метрики через API и складывают
разрезы в `docs/analytics/data/<источник>/<ресурс>/<дата>/*.csv`, а рядом ведут `TREND.md` —
по строке на запуск. Смысл именно в `TREND.md`: цифра за один замер ничего не говорит,
нужна история и колонка «Что меняли», которую заполняешь руками сразу после запуска.

Сырые CSV в git не попадают (`.gitignore`), `TREND.md` и отчёты — попадают.

```bash
pip3 install -r requirements-seo.txt           # разово

python3 scripts/seo/fetch_gsc.py --days 28     # Google Search Console
python3 scripts/seo/fetch_ga4.py --days 28     # GA4 Data API
python3 scripts/seo/fetch_metrika.py --days 28 # Яндекс.Метрика
python3 scripts/seo/fetch_bing.py              # Bing Webmaster Tools

python3 scripts/seo/analyze.py                 # разбор: что работает, что сломано
```

Или всё разом: `scripts/seo/weekly.sh`.

Сайт статический и живёт на GitHub Pages — это инструменты разработчика, в сборку
они не входят и на прод не уезжают.

# Свои заходы не считаются

Бельгия (Антверпен, Брюссель) — это разработчик. На нынешних объёмах пара своих
открытий переписывает всю картину, поэтому свои заходы режутся **на уровне API**, а не
при чтении отчёта: в CSV и в `TREND.md` попадают уже чистые цифры.

Список стран — в [`scripts/seo/config.py`](../../scripts/seo/config.py), по одному на
сервис (названия стран каждый отдаёт по-своему). Посмотреть сырые данные вместе со
своими заходами: `--include-self` у любого из скриптов.

Насколько это меняет картину (замер 10.09.2026):

| | Со своими заходами | Без них |
|---|---|---|
| Метрика, визиты за 28 дней | 13 | **9** |
| Метрика, отказы | 46.2% | **66.7%** |
| GA4, сеансы за 28 дней | 11 | **6** |
| GSC, клики за 90 дней | 3 | **1** |

То есть две трети кликов из Google за квартал были свои. Реальный внешний трафик из
поиска — один клик за три месяца.

# Цели: события в коде

В [`static/app.js`](../../static/app.js) есть обёртка `track(goal, params)` — шлёт событие
сразу в Метрику (`reachGoal`) и в GA4 (`gtag('event', …)`). Если счётчик не загрузился,
вызов молча пропускается: аналитика не должна ронять таймер.

Что уже отправляется:

| Идентификатор | Когда | Параметры |
|---|---|---|
| `timer_start` | нажат старт тренировки | `exercises` — сколько упражнений |
| `workout_complete` | тренировка доведена до конца | `duration_sec` — сколько длилась |
| `workout_create` | создана своя тренировка (не редактирование) | `exercises` |
| `pwa_install` | приложение установлено | `source`: `banner` или `browser` |

В GA4 эти события появятся сами, заводить ничего не надо — смотреть в отчёте «События»
или в `docs/analytics/data/ga4/*/events.csv`.

**В Метрике цели нужно завести руками** — API создания целей требует прав `metrika:write`,
а наш токен только на чтение. Порядок:

<https://metrika.yandex.ru> → счётчик 108311751 → **Настройка** → **Цели** →
**Добавить цель** → тип **JavaScript-событие** → в поле «Идентификатор» вписать значение
из таблицы выше. Четыре раза, по цели на строку. Названия — любые понятные:
«Запуск таймера», «Тренировка завершена», «Своя тренировка создана», «Установка приложения».

После этого `fetch_metrika.py` подхватит их сам — список целей он берёт из API счётчика,
перечислять руками не надо.

Зачем это нужно: сейчас в GA4 из событий только автоматические (`page_view`, `scroll`,
`user_engagement`). По ним нельзя отличить «человек потренировался» от «открыл и закрыл».
Когда трафик появится, без целей выводы делать будет не из чего.

# Bing Webmaster Tools

Не подключён. Скрипт [`fetch_bing.py`](../../scripts/seo/fetch_bing.py) готов и ждёт двух вещей.

**1. Подтвердить сайт.** Проще всего импортом из Search Console — Bing умеет забрать
права оттуда, и мета-тег не понадобится: <https://www.bing.com/webmasters> → **Import
your site from GSC**. Альтернатива — мета-тег `msvalidate.01`, его надо добавить в
`<head>` [`index.html`](../../index.html) рядом с уже стоящими `google-site-verification`
и `yandex-verification`.

**2. Положить API-ключ** в `secrets/bing-api-key.txt`: bing.com/webmasters → шестерёнка
справа вверху → «Доступ к API» → API Key. Ключ один на весь аккаунт, отдельный на каждый
сайт не нужен.

Проверка:

```bash
python3 scripts/seo/fetch_bing.py --sites   # какие сайты видит ключ и подтверждены ли
python3 scripts/seo/fetch_bing.py           # выгрузка по odin-dva.ru
```

`GetRankAndTrafficStats` начинает отдавать данные только когда Bing накопит показы —
первые 2-3 дня после верификации отчёты пустые, это норма, а не поломка.

Зачем вообще: на выдаче Bing сидят Ecosia, Yahoo и DuckDuckGo, и это единственный
источник, который покажет, есть ли сайт в их индексе.

# Разбор данных: `analyze.py`

```bash
python3 scripts/seo/analyze.py            # печатает отчёт и кладёт его в docs/analytics/reports/<дата>.md
python3 scripts/seo/analyze.py --no-save  # только напечатать
```

По сети никуда не ходит (кроме `sitemap.xml`) — читает последние CSV из
`docs/analytics/data/`. Порядок такой: сначала `fetch_*`, потом `analyze`.

| Раздел | Как считает |
|---|---|
| Что работает | страницы с 20+ кликами и CTR выше среднего по сайту |
| Показы есть, кликов нет | 200+ показов и CTR ниже 60% от ожидаемого для этой позиции |
| Запросы у порога топа | позиция 4–15 при 100+ показов |
| Каннибализация | один запрос тянут две и больше страниц |
| Страницы без показов | адреса из `sitemap.xml` без единого показа за период |
| Мобильные и десктоп | разрыв позиций больше двух |
| Счётчики | отказы по страницам входа, internal traffic, сверка Метрики с GA4 |
| Цели | что сработало за период и достаточно ли этого для выводов |
| Bing | клики и показы, когда подключён |

Три решения, которые стоит помнить:

- **Пороги завязаны на средние самого сайта**, а не на «правильные» числа из статей:
  CTR 2% — беда для запроса на первой позиции и норма для десятой.
- **Раздела в отчёте нет — значит по нему ничего не нашлось.** Пустые блоки и таблицы
  без строк не печатаются: пустая шапка читается как поломка отчёта.
- **При маленьких цифрах отчёт говорит об этом прямо.** GSC скрывает разбивку по
  страницам и запросам, пока данных мало: итог за период есть, а строк ноль. Без
  оговорки это читается как «трафика нет вообще» — поэтому скрипт печатает
  предупреждение и блок «Данных мало» вместо пустых таблиц.

# Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `Файл ключа сервис-аккаунта не найден` | ключа нет в `secrets/` | положить `secrets/google-service-account.json` |
| `Не задан OAuth-токен Яндекса` | нет токена | положить `secrets/yandex-metrika-token.txt` |
| GSC: `--list` пуст или 403 | сервис-аккаунт не добавлен в ресурс | GSC → Настройки → Пользователи и разрешения → «Полное» |
| GSC: 403 при выгрузке, хотя `--list` работает | доступ выдан на другой тип ресурса (домен vs префикс URL) | указать `--site` явно |
| GSC: 0 строк постранично при ненулевом итоге | порог приватности Google | ничего; итог смотреть в `TREND.md` |
| `has not been used in project 978861746309` | API выключен в GCP-проекте ключа | включить в console.cloud.google.com/apis/library |
| GA4: `--list` пуст | сервис-аккаунт не добавлен в ресурс GA | GA → Администратор → Управление доступом → «Читатель» |
| GA4: `User does not have sufficient permissions` | доступ есть, но property ID чужой | сверить `529871644` |
| Метрика: `--list` пуст или 403 | токен истёк или выдан без `metrika:read` | перевыпустить на oauth.yandex.ru |
| Bing: 0 строк во всех отчётах | данные ещё не накопились | подождать 2-3 дня после верификации |
| `Не установлены зависимости` | нет google-библиотек | `pip3 install -r requirements-seo.txt` |
